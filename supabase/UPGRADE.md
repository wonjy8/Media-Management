# 기존 프로젝트 업데이트 (이미 001/002를 실행한 경우)

1. Supabase → SQL Editor에서 **UPGRADE.sql 전체**를 복사해 실행합니다.
   - 장비/그룹 관리 권한, 이미지 저장소, 기존 신청 보존, 이력/재고 로직을 추가합니다.
   - 기존 장비·신청을 삭제하지 않습니다. 여러 번 실행할 수 있습니다.
   - 001_initial.sql과 002_workflow.sql을 다시 실행하지 마세요.
2. Edge Functions → equipment-api → Code에서 **functions/equipment-api/index.ts 전체**로 교체 후 배포합니다.
   - 기존 함수 이름과 Verify JWT 해제 설정은 유지합니다.
   - 반납 사진 업로드/관리자 조회가 추가되었습니다.
   - 서비스 키는 코드에 입력하지 않습니다. Supabase가 서버에 제공합니다.
3. 관리자 계정으로 앱에 로그인합니다.
   - **장비 관리 → 그룹**: 그룹 등록/수정
   - **장비 관리 → 장비**: 등록/수정, 이미지, 설명/구성품, 수량, 수리 수량, 비활성화
   - **승인자**: 소속/직위/이름 등록·수정·비활성화 (서식상 활성 승인자 최대 4명)
   - **반출·반납**: 승인, 실제 반출, 부분 반납 현황, 반납 취소, 지연/충돌, 이력과 사진 조회

이미지 정책:
- 장비 대표 이미지는 공개 장비 목록용이므로 공개 equipment-images 버킷입니다.
- 반납 사진은 비공개 return-images 버킷이며 관리자에게만 5분 유효 URL을 발급합니다.
- 둘 모두 파일당 1,000,000바이트 제한. 브라우저에서 압축하고 저장소에서도 제한합니다.

기존 Cron 작업은 그대로 사용하며, UPGRADE.sql이 갱신한 익명화 함수를 실행합니다.
기존 신청에 소속/직위/승인자 스냅샷이 없으면 빈 값으로 남깁니다. 알 수 없는 과거 정보를 추측해 채우지 않습니다.

## 검증 범위

코드/빌드/브라우저와 로컬 PostgreSQL에서 검증합니다.
이 작업자는 공개 키만 있으므로 원격 SQL 적용·Edge 재배포·관리자 로그인은 대신 실행할 수 없습니다.
GitHub Pages 배포 성공은 DB 마이그레이션이나 서버 함수 배포를 뜻하지 않습니다.
